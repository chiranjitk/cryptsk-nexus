   417→
   418→- create
   419→- lookup
   420→- update
   421→- timeout
   422→- CoA
   423→- disconnect
   424→- duplicate-login handling
   425→- stale-session recovery
   426→- reconciliation
   427→- VPP provisioning
   428→- VPP deprovisioning
   429→- ownership
   430→- event ordering
   431→- recovery
   432→
   433→Typical session information includes:
   434→
   435→- session_id
   436→- subscriber/customer/account reference
   437→- username/identity
   438→- NAS
   439→- NAS port/interface
   440→- access protocol
   441→- MAC/device identity
   442→- IPv4/IPv6
   443→- VLAN
   444→- VRF
   445→- policy IDs
   446→- service/plan
   447→- bandwidth profile
   448→- ACL profile
   449→- NAT profile
   450→- DPI profile
   451→- timestamps
   452→- accounting state
   453→- counters/references
   454→- timeout
   455→- session owner
   456→- epoch/generation
   457→- event sequence

   462→
   463→- configuration

   467→- NAS configuration
   468→- historical session records
   469→- accounting records
   470→- audit records
   471→- billing data

   549→# 10. 100,000 CONCURRENT SESSION TARGET
   550→
   551→The product architecture must support:
   552→
   553→**100,000 concurrent active sessions**
   554→
   555→from Day Zero.
   556→
   557→Initial certification may target:
   558→
   559→**50,000 concurrent sessions**
   560→
   561→The architecture must not be redesigned between 50K and 100K.
   562→
   563→The 100K target does NOT mean:
   564→
   565→- 100K threads
   566→- 100K processes
   567→- 100K database connections
   568→- 100K VPP API connections
   569→- 100K policy objects
   570→- 100K SQL transactions
   571→- one worker per subscriber
   572→
   573→Capacity must be measured across:
   574→
   575→- concurrent sessions
   576→- authentication requests/sec
   577→- new sessions/sec
   578→- accounting events/sec
   579→- interim accounting rate
   580→- CoA/sec
   581→- disconnect/sec
   582→- NAT flows
   583→- packets/sec
   584→- throughput
   585→- VPP operations/sec
   586→- database writes/sec
   587→- event/monitoring rate
   588→
   589→Example accounting load:
   590→
   591→```text
   592→100,000 / 300 seconds ≈ 333 events/sec
   593→100,000 / 60 seconds  ≈ 1,667 events/sec
   594→```
   595→
   596→Accounting must therefore be asynchronous/buffered and designed for batching, retry, backpressure, and recovery.

   761→# 17. SESSION LIFECYCLE
   762→
   763→A normal login should follow:
   764→
   765→```text
   766→Authentication
   767→    ↓
   768→Authorization
   769→    ↓
   770→IP allocation
   771→    ↓
   772→Create session
   773→    ↓
   774→Program dataplane
   775→    ↓
   776→Verify dataplane state
   777→    ↓
   778→ACTIVE
   779→    ↓
   780→Accounting
   781→```
   782→
   783→The system must NOT mark a session ACTIVE before required dataplane provisioning succeeds.
   784→
   785→Logout may be triggered by:
   786→
   787→- Accounting-Stop
   788→- timeout
   789→- CoA/Disconnect
   790→- administrator
   791→- duplicate-login policy
   792→- account expiry
   793→- IP conflict
   794→- NAS failure/reconciliation
   795→- gateway policy
   796→- session termination
   797→
   798→Normal logout:
   799→
   800→```text
   801→Locate session
   802→ ↓
   803→Mark disconnecting
   804→ ↓
   805→Remove dataplane state
   806→ ↓
   807→Release IP/resource
   808→ ↓
   809→Finalize accounting
   810→ ↓
   811→Persist history
   812→ ↓
   813→DISCONNECTED
   814→```
   815→
   816→Use idempotency and epoch/generation to prevent stale events from deleting a newer session.

  1427→          +-----------------+-----------------+

  1452→Session Engine owns live subscriber lifecycle.  
  1453→Policy Engine translates business policy.

  1455→DPDK handles high-performance packet I/O.  
  1456→PostgreSQL stores durable business and historical state.  
  1457→The UI configures and observes the system; it does not become the dataplane.**
  1458→
  1459→This is the architecture to design first.
  1460→
  1461→Development begins only after this architecture and its subordinate domain specifications are internally consistent.
