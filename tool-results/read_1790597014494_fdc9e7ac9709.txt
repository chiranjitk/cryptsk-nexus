    42→    42→
    43→    43→``` text

   132→   132→# 4. Session Engine
   133→   133→
   134→   134→The Session Engine is the core new component.
   135→   135→
   136→   136→It owns the authoritative live subscriber/session state.
   137→   137→
   138→   138→Example:
   139→   139→
   140→   140→``` text
   141→   141→Session ID
   142→   142→Username
   143→   143→Subscriber ID
   144→   144→NAS ID
   145→   145→Access protocol
   146→   146→IPv4
   147→   147→IPv6
   148→   148→MAC
   149→   149→VLAN
   150→   150→Interface
   151→   151→VRF
   152→   152→Authentication time
   153→   153→Last accounting update
   154→   154→Session state
   155→   155→Policy ID
   156→   156→Bandwidth profile
   157→   157→QoS profile
   158→   158→ACL profile
   159→   159→NAT profile
   160→   160→IP pool
   161→   161→Accounting state
   162→   162→Data counters
   163→   163→Packet counters
   164→   164→Idle timeout
   165→   165→Session timeout
   166→   166→Device information
   167→   167→```
   168→   168→
   169→   169→The Session Engine MUST be independent from FreeRADIUS.
   170→   170→
   171→   171→------------------------------------------------------------------------
   172→   172→
   173→   173→# 5. Why Session Engine Must Be Separate
   174→   174→
   175→   175→RADIUS is a request/response AAA protocol.
   176→   176→
   177→   177→A subscriber session may remain online for:
   178→   178→
   179→   179→-   minutes
   180→   180→-   hours
   181→   181→-   days
   182→   182→-   weeks
   183→   183→
   184→   184→The RADIUS Access-Accept is only the authentication decision.
   185→   185→
   186→   186→Therefore:
   187→   187→
   188→   188→``` text
   189→   189→RADIUS request
   190→   190→      ↓
   191→   191→Authentication decision
   192→   192→      ↓
   193→   193→Access-Accept
   194→   194→      ↓
   195→   195→Session Engine creates live session
   196→   196→      ↓
   197→   197→VPP enforces policy
   198→   198→```
   199→   199→
   200→   200→The session continues even when there is no RADIUS packet.
   201→   201→

   259→   259→Subscriber
   260→   260→    ↓
   261→   261→NAS
   262→   262→    ↓
   263→   263→RADIUS Access-Request
   264→   264→    ↓
   265→   265→FreeRADIUS
   266→   266→    ↓
   267→   267→Authentication
   268→   268→    ↓
   269→   269→Authorization
   270→   270→    ↓
   271→   271→Access-Accept
   272→   272→    ↓
   273→   273→Session Engine
   274→   274→    ↓
   275→   275→Create session
   276→   276→    ↓
   277→   277→Allocate IP
   278→   278→    ↓
   279→   279→Resolve subscriber policy
   280→   280→    ↓
   281→   281→Generate dataplane policy
   282→   282→    ↓

   284→   284→    ↓
   285→   285→VPP
   286→   286→    ↓
   287→   287→Subscriber becomes ACTIVE
   288→   288→```
   289→   289→
   290→   290→------------------------------------------------------------------------
   291→   291→
   292→   292→# 8. Login Must Be Transactional
   293→   293→
   294→   294→Do NOT mark the subscriber ACTIVE before dataplane programming succeeds.
   295→   295→
   296→   296→Correct sequence:
   297→   297→
   298→   298→``` text
   299→   299→1. Authenticate
   300→   300→2. Authorize
   301→   301→3. Allocate IP
   302→   302→4. Create session
   303→   303→5. Program VPP
   304→   304→6. Verify VPP programming
   305→   305→7. Mark ACTIVE
   306→   306→8. Start accounting
   307→   307→```
   308→   308→
   309→   309→If VPP programming fails:
   310→   310→
   311→   311→``` text
   312→   312→Authentication successful
   313→   313→        ↓
   314→   314→VPP programming failed
   315→   315→        ↓
   316→   316→Session NOT ACTIVE
   317→   317→        ↓
   318→   318→Return controlled failure
   319→   319→```
   320→   320→
   321→   321→Do not create "ghost sessions".
   322→   322→
   323→   323→------------------------------------------------------------------------

   325→   325→# 9. Logout
   326→   326→
   327→   327→Logout may originate from:
   328→   328→
   329→   329→-   NAS Accounting-Stop
   330→   330→-   RADIUS Disconnect
   331→   331→-   CoA
   332→   332→-   session timeout
   333→   333→-   idle timeout
   334→   334→-   administrative disconnect
   335→   335→-   duplicate login policy
   336→   336→-   IP conflict
   337→   337→-   NAS failure recovery
   338→   338→-   system policy
   339→   339→-   subscriber suspension
   340→   340→-   account expiry
   341→   341→
   342→   342→Flow:
   343→   343→
   344→   344→``` text
   345→   345→Logout Event
   346→   346→     ↓
   347→   347→Session Engine
   348→   348→     ↓
   349→   349→Locate session
   350→   350→     ↓
   351→   351→Mark DISCONNECTING
   352→   352→     ↓
   353→   353→Remove VPP policy/state
   354→   354→     ↓
   355→   355→Release IP
   356→   356→     ↓
   357→   357→Close accounting state
   358→   358→     ↓
   359→   359→Persist final session record
   360→   360→     ↓
   361→   361→Mark DISCONNECTED
   362→   362→```
   363→   363→
   364→   364→Operations MUST be idempotent.
   365→   365→
   366→   366→Calling logout twice must not corrupt state.
   367→   367→

   486→   486→# 13. PostgreSQL Responsibilities
   487→   487→
   488→   488→PostgreSQL is the durable source of configuration, identity,
   489→   489→accounting-history, audit, and recovery metadata.
   490→   490→
   491→   491→It is NOT the authoritative real-time store for packet-path state or the
   492→   492→sole source of truth for live session ownership.
   493→   493→
   494→   494→Live session state is authoritative in the Session Engine; PostgreSQL
   495→   495→provides durable configuration/history and recovery persistence.
   496→   496→
   497→   497→Use PostgreSQL for:
   498→   498→
   499→   499→-   subscribers
   500→   500→-   credentials
   501→   501→-   subscriber profiles
   502→   502→-   service plans
   503→   503→-   policies
   504→   504→-   NAS definitions
   505→   505→-   IP pools
   506→   506→-   VLANs
   507→   507→-   gateway configuration
   508→   508→-   accounting history
   509→   509→-   session history
   510→   510→-   audit logs
   511→   511→-   administrator data
   512→   512→-   configuration
   513→   513→-   billing information
   514→   514→
   515→   515→Do NOT use PostgreSQL as the packet-path state store.
   516→   516→
   517→   517→------------------------------------------------------------------------
   518→   518→

   524→   524→Example:
   525→   525→
   526→   526→``` text
   527→   527→Session Engine
   528→   528→      │
   529→   529→      ├── HashMap / concurrent map
   530→   530→      ├── IP → Session index

   533→   533→      ├── Session-ID → Session index
   534→   534→      └── NAS → session index
   535→   535→```
   536→   536→
   537→   537→Optional Redis can be used for:
   538→   538→
   539→   539→-   HA coordination

   541→   541→-   temporary state
   542→   542→-   event distribution
   543→   543→-   shared cache
   544→   544→
   545→   545→But Redis should not automatically become the packet-path database.

   549→   549→# 15. 100,000 Session Architectural Target
   550→   550→
   551→   551→The platform MUST be architected for 100,000 concurrent sessions from
   552→   552→day one.
   553→   553→
   554→   554→The first production/certification profile may be 50,000 sessions, but
   555→   555→the software architecture must not contain a 50k-specific ceiling.
   556→   556→
   557→   557→100,000 concurrent sessions is not itself a difficult memory problem.
   558→   558→The real scalability dimensions are:
   559→   559→
   560→   560→The real scalability dimensions are:
   561→   561→
   562→   562→``` text
   563→   563→Concurrent sessions
   564→   564→+
   565→   565→Authentication requests/sec
   566→   566→+
   567→   567→Accounting packets/sec
   568→   568→+
   569→   569→CoA/sec
   570→   570→+
   571→   571→Disconnect/sec
   572→   572→+
   573→   573→New sessions/sec
   574→   574→+
   575→   575→Database writes/sec
   576→   576→+
   577→   577→VPP policy operations/sec
   578→   578→+
   579→   579→NAT flows
   580→   580→+
   581→   581→Packets/sec
   582→   582→+
   583→   583→Bandwidth
   584→   584→```
   585→   585→
   586→   586→The architecture MUST therefore define capacity independently for each
   587→   587→dimension.
   588→   588→

   590→   590→
   591→   591→# 16. Example Accounting Load
   592→   592→
   593→   593→For 100,000 active sessions:
   594→   594→
   595→   595→With 5-minute interim updates:
   596→   596→
   597→   597→``` text
   598→   598→100,000 / 300
   599→   599→≈ 333 accounting updates/sec
   600→   600→```
   601→   601→
   602→   602→With 1-minute interim updates:
   603→   603→
   604→   604→``` text
   605→   605→100,000 / 60
   606→   606→≈ 1,667 accounting updates/sec
   607→   607→```
   608→   608→
   609→   609→Therefore, do NOT blindly configure 60-second SQL accounting updates for
   610→   610→every deployment.
   611→   611→
   612→   612→Make the accounting interval configurable.
   613→   613→
   614→   614→Recommended defaults:
   615→   615→
   616→   616→``` text
   617→   617→Interim update:
   618→   618→300 seconds
   619→   619→
   620→   620→High-accuracy mode:
   621→   621→60–120 seconds
   622→   622→
   623→   623→Low-load mode:
   624→   624→300–600 seconds
   625→   625→```
   626→   626→
   627→   627→The final choice must depend on billing/audit requirements.
   628→   628→
   629→   629→------------------------------------------------------------------------
   630→   630→

   646→   646→ ↓
   647→   647→Accounting Writer

   651→   651→
   652→   652→For high-load installations:
   653→   653→
   654→   654→``` text

   657→   657→fast acknowledgement

   669→   669→# 18. Accounting Tables
   670→   670→
   671→   671→Do not allow `radacct` to grow indefinitely as one unpartitioned table.
   672→   672→
   673→   673→Use time partitioning.
   674→   674→
   675→   675→Example:
   676→   676→
   677→   677→``` text
   678→   678→radacct
   679→   679→ ├── 2026_09
   680→   680→ ├── 2026_10
   681→   681→ ├── 2026_11
   682→   682→ └── ...
   683→   683→```
   684→   684→
   685→   685→Indexes should be designed around actual queries.
   686→   686→
   687→   687→Important lookup dimensions:
   688→   688→
   689→   689→``` text
   690→   690→session_id
   691→   691→acct_session_id

   706→   706→# 19. Authentication Cache
   707→   707→
   708→   708→Authentication can use multiple levels:
   709→   709→
   710→   710→``` text
   711→   711→L1:
   712→   712→Session Engine / local cache
   713→   713→
   714→   714→L2:
   715→   715→Redis optional
   716→   716→
   717→   717→L3:
   718→   718→PostgreSQL / LDAP / AD
   719→   719→
   720→   720→L4:
   721→   721→External authentication backend
   722→   722→```
   723→   723→
   724→   724→However, credentials and security-sensitive data must not be cached
   725→   725→indiscriminately.
   726→   726→
   727→   727→Cache authorization/profile data more aggressively than passwords.
   728→   728→
   729→   729→Example:
   730→   730→
   731→   731→``` text
   732→   732→Subscriber
   733→   733→   ↓

   737→   737→   ↓
   738→   738→Policy ID
   739→   739→```

   741→   741→------------------------------------------------------------------------
   742→   742→
   743→   743→# 20. FreeRADIUS Threading
   744→   744→
   745→   745→FreeRADIUS uses a thread pool.
   746→   746→
   747→   747→The configuration must be tuned based on:
   748→   748→
   749→   749→-   CPU cores
   750→   750→-   request rate
   751→   751→-   authentication backend latency
   752→   752→-   SQL latency
   753→   753→-   LDAP latency
   754→   754→-   EAP workload
   755→   755→-   accounting load
   756→   756→
   757→   757→Do not simply configure hundreds of threads because there are 100,000
   758→   758→sessions.
   759→   759→
   760→   760→100,000 sessions ≠ 100,000 FreeRADIUS threads.
   761→   761→
   762→   762→Thread count must be derived from request rate, backend latency,
   763→   763→protocol mix, CPU, and measured queueing behavior.
   764→   764→
   765→   765→A session is not a FreeRADIUS worker.
   766→   766→
   767→   767→------------------------------------------------------------------------

  1286→  1286→
  1287→  1287→The gateway platform may provide an explicit Web Browsing / HTTP Logs capability for traffic where the deployment and protocol visibility make the required fields technically available.
  1288→  1288→
  1289→  1289→The canonical distinction is:
  1290→  1290→
  1291→  1291→```text
  1292→  1292→NAT Logs
  1293→  1293→  = private/source ↔ translated/public address and port traceability
  1294→  1294→
  1295→  1295→Web Browsing / HTTP Logs
  1296→  1296→  = HTTP request/browsing metadata where visible and permitted
  1297→  1297→
  1298→  1298→DPI / Application Awareness
  1299→  1299→  = protocol/application classification and usage intelligence
  1300→  1300→```
  1301→  1301→
  1302→  1302→For encrypted HTTPS traffic, the product MUST NOT claim visibility into URL paths or payload content unless an explicitly approved inspection/decryption architecture provides that visibility. Standard deployments may record available metadata such as timestamp, source/session identity, destination address, host/domain metadata where available, method/status for visible HTTP traffic, and correlation identifiers.
  1303→  1303→
  1304→  1304→Retention, privacy, access control, and export behavior MUST follow the security and observability specifications.

  1360→  1360→ALLOW_MULTIPLE
  1361→  1361→DENY_NEW
  1362→  1362→DISCONNECT_OLD
  1363→  1363→LIMIT_N
  1364→  1364→```
  1365→  1365→
  1366→  1366→Example:
  1367→  1367→
  1368→  1368→``` text
  1369→  1369→User = john
  1370→  1370→Simultaneous sessions = 2
  1371→  1371→
  1372→  1372→Session 1 → active
  1373→  1373→Session 2 → active
  1374→  1374→Session 3 → reject
  1375→  1375→```
  1376→  1376→
  1377→  1377→For `DISCONNECT_OLD`:
  1378→  1378→
  1379→  1379→``` text
  1380→  1380→new login
  1381→  1381→   ↓
  1382→  1382→find old session
  1383→  1383→   ↓
  1384→  1384→disconnect old
  1385→  1385→   ↓
  1386→  1386→create new session
  1387→  1387→```
  1388→  1388→
  1389→  1389→------------------------------------------------------------------------
  1390→  1390→
  1391→  1391→# 39. Stale Session Recovery
  1392→  1392→
  1393→  1393→Never rely exclusively on Accounting-Stop.
  1394→  1394→
  1395→  1395→NAS devices can:
  1396→  1396→
  1397→  1397→-   reboot
  1398→  1398→-   lose connectivity
  1399→  1399→-   crash
  1400→  1400→-   lose RADIUS connectivity
  1401→  1401→-   lose accounting packets
  1402→  1402→
  1403→  1403→Implement:
  1404→  1404→
  1405→  1405→``` text
  1406→  1406→Accounting-Stop
  1407→  1407→+
  1408→  1408→Interim-Update
  1409→  1409→+
  1410→  1410→Session timeout
  1411→  1411→+
  1412→  1412→NAS health
  1413→  1413→+
  1414→  1414→stale-session detector
  1415→  1415→```
  1416→  1416→
  1417→  1417→Session Engine should periodically identify sessions whose accounting
  1418→  1418→state has expired.
  1419→  1419→
  1420→  1420→------------------------------------------------------------------------
  1421→  1421→
  1422→  1422→# 40. Session Reconciliation
  1423→  1423→
  1424→  1424→After gateway restart:
  1425→  1425→
  1426→  1426→``` text
  1427→  1427→VPP state
  1428→  1428→     +
  1429→  1429→Session database
  1430→  1430→     +
  1431→  1431→RADIUS accounting
  1432→  1432→     +
  1433→  1433→NAS state
  1434→  1434→```
  1435→  1435→
  1436→  1436→must be reconciled.
  1437→  1437→
  1438→  1438→Do not assume:
  1439→  1439→
  1440→  1440→``` text
  1441→  1441→process restarted = all users disconnected
  1442→  1442→```
  1443→  1443→
  1444→  1444→Design recovery states:
  1445→  1445→
  1446→  1446→``` text
  1447→  1447→RECOVERING
  1448→  1448→     ↓
  1449→  1449→Reconcile
  1450→  1450→     ↓
  1451→  1451→ACTIVE
  1452→  1452→```
  1453→  1453→
  1454→  1454→or:
  1455→  1455→
  1456→  1456→``` text
  1457→  1457→STALE
  1458→  1458→     ↓
  1459→  1459→Cleanup
  1460→  1460→```
  1461→  1461→
  1462→  1462→------------------------------------------------------------------------
  1463→  1463→
  1464→  1464→# 41. VPP Restart Recovery
  1465→  1465→
  1466→  1466→If VPP crashes/restarts:
  1467→  1467→
  1468→  1468→``` text
  1469→  1469→VPP restart
  1470→  1470→    ↓
  1471→  1471→Session Engine detects VPP reconnect
  1472→  1472→    ↓
  1473→  1473→Load active session snapshot
  1474→  1474→    ↓
  1475→  1475→Rebuild VPP policies
  1476→  1476→    ↓
  1477→  1477→Rebuild required NAT/policy state
  1478→  1478→    ↓

  1486→  1486→

  1516→  1516→# 43. High Availability
  1517→  1517→
  1518→  1518→HA MUST be separated into clearly defined service levels:
  1519→  1519→
  1520→  1520→1.  Control-plane HA
  1521→  1521→2.  Session/state HA
  1522→  1522→3.  Stateful dataplane/NAT HA
  1523→  1523→
  1524→  1524→The product must not advertise "stateful HA" merely because PostgreSQL
  1525→  1525→and management services are replicated.
  1526→  1526→
  1527→  1527→For enterprise deployments:
  1528→  1528→
  1529→  1529→``` text
  1530→  1530→                 ┌──────────────┐
  1531→  1531→                 │ PostgreSQL HA│
  1532→  1532→                 └──────┬───────┘
  1533→  1533→                        │
  1534→  1534→             ┌──────────┴──────────┐
  1535→  1535→             │                     │
  1536→  1536→       Gateway Node A        Gateway Node B
  1537→  1537→             │                     │
  1538→  1538→        VPP + Session          VPP + Session
  1539→  1539→             │                     │
  1540→  1540→             └──────────┬──────────┘
  1541→  1541→                        │
  1542→  1542→                     Network
  1543→  1543→```
  1544→  1544→
  1545→  1545→HA design should distinguish:
  1546→  1546→
  1547→  1547→### Control-plane HA
  1548→  1548→
  1549→  1549→Easy to replicate:
  1550→  1550→
  1551→  1551→-   configuration
  1552→  1552→-   policies
  1553→  1553→-   subscribers
  1554→  1554→-   NAS
  1555→  1555→-   accounting
  1556→  1556→
  1557→  1557→### Dataplane/session HA
  1558→  1558→
  1559→  1559→Much harder:
  1560→  1560→
  1561→  1561→-   active NAT state
  1562→  1562→-   active flows
  1563→  1563→-   subscriber state
  1564→  1564→-   packet counters
  1565→  1565→
  1566→  1566→Do not claim stateful HA until actual state replication is implemented
  1567→  1567→and tested.
  1568→  1568→
  1569→  1569→------------------------------------------------------------------------
  1570→  1570→

  1623→  1623→# 46. IPAM
  1624→  1624→
  1625→  1625→Create a dedicated IPAM module.
  1626→  1626→
  1627→  1627→For 100k-scale operation, IPAM MUST use an in-memory allocation
  1628→  1628→structure plus durable recovery state. PostgreSQL transactions may be
  1629→  1629→used for authoritative persistence and conflict prevention, but IP
  1630→  1630→allocation must not require a full SQL round-trip for every subscriber
  1631→  1631→when the system is under high login churn.
  1632→  1632→
  1633→  1633→Responsibilities:
  1634→  1634→
  1635→  1635→``` text
  1636→  1636→Pool creation
  1637→  1637→Pool deletion
  1638→  1638→Pool status
  1639→  1639→Free IP count
  1640→  1640→Allocated IP count
  1641→  1641→Reservation
  1642→  1642→Static IP
  1643→  1643→Dynamic IP
  1644→  1644→Lease
  1645→  1645→Expiration
  1646→  1646→Subscriber mapping
  1647→  1647→```
  1648→  1648→
  1649→  1649→For very high-concurrency allocation, use transactional allocation.
  1650→  1650→
  1651→  1651→Avoid:
  1652→  1652→
  1653→  1653→``` text
  1654→  1654→SELECT free IP
  1655→  1655→↓
  1656→  1656→application waits
  1657→  1657→↓
  1658→  1658→UPDATE IP
  1659→  1659→```
  1660→  1660→
  1661→  1661→because concurrent workers can collide.
  1662→  1662→
  1663→  1663→Use atomic/transactional allocation.
  1664→  1664→
  1665→  1665→------------------------------------------------------------------------
  1666→  1666→
  1667→  1667→# 47. IP Pool Model
  1668→  1668→
  1669→  1669→``` text
  1670→  1670→IP Pool
  1671→  1671→ ├── pool_id
  1672→  1672→ ├── name
  1673→  1673→ ├── network
  1674→  1674→ ├── gateway
  1675→  1675→ ├── VLAN
  1676→  1676→ ├── VRF
  1677→  1677→ ├── allocation mode
  1678→  1678→ ├── static/dynamic

  1681→  1681→
  1682→  1682→Allocation:
  1683→  1683→
  1684→  1684→``` text
  1685→  1685→subscriber
  1686→  1686→    ↓

  1697→  1697→
  1698→  1698→# 48. IPAM Performance
  1699→  1699→
  1700→  1700→If SQL-based IP allocation is used, use proper transactional allocation
  1701→  1701→and avoid lock contention.
  1702→  1702→
  1703→  1703→The FreeRADIUS project specifically documents
  1704→  1704→`SELECT ... FOR UPDATE SKIP LOCKED` and stored procedures as mechanisms
  1705→  1705→for high-concurrency SQL IP allocation.
  1706→  1706→
  1707→  1707→For a very high-throughput gateway, however, the preferred architecture
  1708→  1708→is:
  1709→  1709→
  1710→  1710→``` text
  1711→  1711→IPAM service
  1712→  1712→     ↓
  1713→  1713→in-memory free-address structures
  1714→  1714→     ↓
  1715→  1715→durable state asynchronously persisted
  1716→  1716→```
  1717→  1717→
  1718→  1718→while retaining transactional recovery semantics.
  1719→  1719→
